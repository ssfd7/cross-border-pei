For showing an answer in its setting, not for computing one: use the other computations for figures. `relation` is `holds`, `jurisdictionFact` or `payment`. Holdings and jurisdiction facts are those from the system of record that are valid on the date; payments are those made on or before it. A holding's `label` is its economic percentage and capacity; it is the percentage of that one interest, not an effective holding through the chain.

`source_refs` and `target_refs` list the same party in each source system, so an investor number or a counterparty identifier can be matched to its node.

# Computation

```cypher
MATCH (a:Party)-[r:HOLDS|JURISDICTION_FACT|PAYMENT]->(b)
WHERE (label(r) = 'PAYMENT' AND r.occurredOn <= date($on_date))
   OR (label(r) <> 'PAYMENT' AND r.systemOfRecord AND (r.validFrom IS NULL OR r.validFrom <= date($on_date))
       AND (r.validTo IS NULL OR r.validTo >= date($on_date)))
RETURN CASE label(r) WHEN 'HOLDS' THEN 'holds' WHEN 'PAYMENT' THEN 'payment' ELSE 'jurisdictionFact' END AS relation,
       a.id AS source, a.name AS source_name,
       CASE WHEN a.isFundVehicle THEN 'FundVehicle' WHEN a.isSPV THEN 'SPV' WHEN a.isPortfolioCompany THEN 'PortfolioCompany' ELSE a.kind END AS source_kind,
       a.sourceRefs AS source_refs, b.id AS target, b.name AS target_name,
       CASE WHEN label(b) = 'Jurisdiction' THEN 'Jurisdiction' WHEN b.isFundVehicle THEN 'FundVehicle' WHEN b.isSPV THEN 'SPV'
            WHEN b.isPortfolioCompany THEN 'PortfolioCompany' ELSE b.kind END AS target_kind,
       b.sourceRefs AS target_refs,
       CASE label(r) WHEN 'HOLDS' THEN CAST(r.economicPercentage AS STRING) + '% ' + r.holdingCapacity
                     WHEN 'PAYMENT' THEN r.identifier + ' ' + r.paymentType ELSE r.factType END AS label,
       r.sourceRef AS source_ref
ORDER BY relation, source, target, label, source_ref
```
